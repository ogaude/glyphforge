# Recipes

A recipe is a YAML (`.yaml`, `.yml`) or TOML (`.toml`) file that fully describes a run. It is validated by a pydantic model with extra fields forbidden, so a misspelled key is an error, never silently ignored. The committed JSON Schema is [`src/glyphforge/recipe/schema.json`](../src/glyphforge/recipe/schema.json); it is regenerated by `glyphforge validate <recipe> --schema <file>` and CI fails if the committed copy drifts.

The same recipe and seed always produce the same dataset. The recipe hash (`recipe_sha256`, shown by `validate`, `plan` and `run`) is the sha256 of the canonical JSON dump of the validated recipe and is stored on every sample.

Committed recipes:

- `recipes/grammar-small.yaml`: grammar only, no pinned files, runs in minutes.
- `recipes/mix-small.yaml`: grammar 0.3 plus mutation 0.7; the mutation part pins `source/glyphfix-train.jsonl` by sha256; no export section.
- `recipes/glyphforge-equations-v1.yaml`: the published dataset; mutation pin `source/glyphfix-train.jsonl`, `export.blocklist.path: source/blocklist.jsonl`, format `parquet`, no degradation.

## Pinned files

Every `path` in a recipe (mutation source, blocklist) resolves relative to the recipe file's directory and may not escape it. Its sha256 is always verified; a mismatch fails the run (exit 1). `recipes/source/` is not committed; see [reproducibility](reproducibility.md) for how to fill it.

## Top-level keys

### schema_version

Must be `3`.

### seed

Non-negative integer, default `0`. Per-sample seeds are derived from it, so any sample can be regenerated alone.

### source

`kind` is one of:

- `builtin` (default): the bundled seed formulas; takes no licence.
- `inline`: `formulas` listed in the recipe (strings or mappings); requires `licence`.
- `file`: formulas from `path`; requires `licence`.
- `grammar`: the synthetic grammar; optional `domains` weights over `math`, `astro-ph`, `physics`. No licence field (rows are CC0-1.0).
- `mutation`: formulas from a pinned snapshot; requires `path` and `sha256`; optional `max_sites` (1 to 3).
- `mix`: exactly two non-mix `parts` (one grammar, one mutation) plus `shares` (each in (0, 1), summing to 1). When omitted for a grammar plus mutation pair the default is 0.3 for grammar and 0.7 for mutation, in whichever order the parts are listed.

`licence` is one of `CC0-1.0`, `CC-BY-3.0`, `CC-BY-4.0`. See [sources and licensing](sources-and-licensing.md).

### classes

Optional list of error-class names to use; default is every registered class. See [error classes](error-classes.md).

### plugins and entry_points

`plugins` is a list of dotted module names, each providing `register_classes(registry)`. `entry_points: true` also loads classes from the `glyphforge.error_classes` entry-point group.

### qc

`ambiguity`: `drop` (default) removes samples whose alternative label renders to identical pixels; `flag` keeps them with a flag.

### styles

Optional list of named LaTeX styles (`name`, `font` in `cm`, `lmodern`, `mathpazo`, `newtx`, `libertine`, `stix2`, `size` 8 to 12, `packages`, `weight`). Names must be unique. The default set is `default`, `cmbright` and `libertine`.

### typography

Weights for `fonts`, `sizes` (8 to 12), `site_levels` (`base`, `script`, `scriptscript`) and extra `packages`. Defaults come from the bundled `typography.yaml`.

### structure

`kinds` weights over `display`, `inline`, `numbered` (default all display); `column_cm` weights (keys 5 to 30); `multiline` (0.2), `punct_prob` (0.2), `text_prob` (0.8), each in [0, 1].

### composition

`total` (default 100), optional per-class `shares` (non-negative, summing to 1), `hard_negative_ratio` (default 1.0, at least 1.0), `attempt_cap` (default 5, at most 20).

### bounds

`max_tokens` (500), `token_margin` (60), `max_depth` (6), `max_scripts` (12). The token cap actually applied is `max_tokens - token_margin`.

### render

`pad_px`: padding in pixels around the ink crop, default 0, at most 64.

### export

- `formats`: any of `glyphfix`, `parquet`, unique. A non-empty list requires `blocklist`; the leak gate has no skip.
- `blocklist`: `path` and `sha256` of the pinned blocklist.
- `shard_mb` (500), `row_group_rows` (1000).
- `degrade`: optional degradation, applied after QC to the clean render. `clean_share` keeps that fraction of samples clean; the operations `contrast`, `rotate`, `blur`, `noise`, `jpeg` each take `p`, `min` and `max` within fixed caps. Degradation is off unless this section is present, and the published dataset uses none. Which operations ran is recorded per sample.

See [export](export.md) for what an export writes.

## Minimal example

```yaml
schema_version: 3
seed: 1
source:
  kind: mix
  parts:
    - kind: grammar
    - kind: mutation
      path: source/glyphfix-train.jsonl
      sha256: "<64 hex digits>"
composition:
  total: 200
export:
  formats: [parquet]
  blocklist:
    path: source/blocklist.jsonl
    sha256: "<64 hex digits>"
```
